01 要件定義書
1.1 プロジェクト概要

目的

NYSEO出力データをもとに、被リンク不足記事（被リンク数1件以下）に対して、関連性の高い他記事から内部リンクを設置する候補を自動提案し、SEO内部リンク構築業務を半自動化する。

💡 最終的な内部リンク設置はクライアント担当者様が確認・判断することを想定しています。WordPressへの自動反映は本フェーズでは対象外となります。

主要機能

  • 被リンク不足記事の自動抽出（E列 ≤ 1）
  • メインKW（C列）を起点とした関連記事探索（KW一致・部分一致・関連語・共起語・類義語）
  • 候補記事のHTML解析（title / h1 / h2 / h3 / 本文）
  • Claude AIによる関連性スコアリング（100点満点・5観点）
  • 内部リンク設置候補のCSV出力（H列以降）
1.2 ユーザー・権限定義
ロール説明できることできないこと
システム運用者
エージェント実行者		 Cowork上でエージェントを起動する エージェント実行・再実行・ログ確認 WordPress自動投稿（本フェーズ対象外）
クライアント担当者
レビュアー		 提案結果を確認・レビューする 出力CSV閲覧・内部リンク実施の最終判断 エージェントの直接操作
1.3 機能要件（5ステップ処理）
1
STEP1 — 対象記事抽出・KW取得
  • 入力CSVのE列（被リンク数）を全行読み取る
  • E列 ≤ 1 かつ N列（処理済みフラグ）が空白の行を対象に選定する
  • 対象行のB列（記事URL）・C列（メインKW）を取得する
  • C列にKWが入っている場合：そのKWをSTEP2の起点として使用する
  • C列が空白の場合：B列のURLから記事を取得し、<title> / <h1> / <h2> / <h3>（本文見出し全体）を解析してメインKWを自動検出する（全記事を対象にするため）
  • B列が空の場合のみその行をスキップしてログに記録する
2
STEP2 — 関連記事候補探索
  • STEP1で取得したメインKW（C列またはtitle/h1/h2/h3から自動検出）を起点とする
  • CSV内の全記事（約231件）のtitle/h1/h2/h3を事前に一括取得する
  • Claude APIを用いてKWの関連語・共起語・類義語を生成し探索範囲を拡張する
  • KW一致・部分一致＋取得したコンテンツ内容を組み合わせて候補を絞り込む
  • 対象記事自身のURL・すでに採用済みのURLは除外する
3
STEP3 — 候補記事取得・解析
  • 各候補記事URLへHTTPSリクエストを送信する（タイムアウト10秒）
  • BeautifulSoupで以下を抽出: <title>・<h1>・<h2>/<h3>一覧・本文テキスト（先頭800文字）
  • HTTP失敗（404・タイムアウト等）はスキップ・警告ログ出力・処理継続する
  • 最大2回リトライ後に失敗した場合は候補から除外する
4
STEP4 — AI関連性判定
  • Claude APIを使用し、5観点で関連性を100点満点でスコアリングする
  • スコア ≥ 60点の記事を採用候補とする
  • 候補が2件未満の場合は閾値を40点に下げて再判定する
  • 採用候補記事の中で、対象記事へのリンクを設置するのに最適な「見出し箇所」もAIが合わせて提案する
5
STEP5 — 内部リンク設置候補生成・出力
  • 採用候補をスコア降順で並び替え、上位2〜3件を出力CSVに書き込む
  • H列: 候補記事URL①（この記事から対象記事へリンクを設置）/ I列: リンク設置箇所見出し①（候補記事内の見出し）
  • J列: 候補記事URL② / K列: リンク設置箇所見出し② / 3件目はL列・M列に出力する
  • 処理完了後にN列へ「done」フラグを書き込む

03 AI判定ロジック設計
3.1 関連性スコアリング設計
判定観点重み配点判定内容
検索意図一致度30%0〜30点対象記事を読むユーザーの検索意図と候補記事が一致するか
トピック一致度25%0〜25点扱っているトピック・テーマが同一または密接に関連しているか
文脈自然性20%0〜20点対象記事の文中で候補記事へのリンクが自然に機能するか
SEO妥当性15%0〜15点SEO観点でリンク元→リンク先のテーマ関連性が適切か
内部リンク自然性10%0〜10点具体的なアンカーテキストとしてリンクが機能するか
合計100%0〜100点
3.2 判定基準・閾値設定
スコア評価採用判定
80〜100点強く関連あり✅ 優先採用（最上位で出力）
60〜79点関連あり✅ 通常採用
40〜59点やや関連あり⚠️ 候補が2件未満の場合のみ採用（閾値下げ時）
0〜39点関連なし❌ 除外
3.3 除外条件
  • 対象記事自身のURLと同一（自己リンク防止）
  • スコア < 40点（最低閾値ライン）
  • HTTP取得に失敗した記事（404・タイムアウト等）
  • カテゴリページ・タグページ・アーカイブページ（/category/・/tag/・/page/ 含むURL）
  • 同一対象記事内でH列以降にすでに提案済みのURL

あなたはSEO専門家です。以下の2記事の関連性を評価してください。

## 対象記事（被リンクを増やしたい記事・E列≤1の記事）
- メインKW: {target_kw}
- URL: {target_url}

## 候補記事（対象記事へのリンクを設置する側の記事）
- タイトル: {candidate_title}
- URL: {candidate_url}
- 主要見出し: {candidate_headings}
- 本文冒頭: {candidate_body[:800]}

- 検索意図一致度 (0-30点)
- トピック一致度 (0-25点)
- 文脈自然性 (0-20点)
- SEO妥当性 (0-15点)
- 内部リンク自然性 (0-10点)

## 出力形式（JSON）
{
  "score": 整数(0-100),
  "reason": "判定理由（1-2文で簡潔に）",
  "recommended_heading": "候補記事内で対象記事へのリンクを設置するのに最適な見出しテキスト"
}
04 データ設計
4.1 CSV 列定義
📋 A〜G列はNYSEO出力データ（入力領域）、H列以降はシステムの出力領域です。入力CSVをそのまま読み込み、H〜N列を追記した出力CSVを生成します。N列（処理済みフラグ）を削除すると再実行されます。
🔗 リンク方向について：H列以降に出力される「候補記事URL」は、その記事から対象記事（E列≤1の記事）へ内部リンクを新たに設置する記事です。対象記事の被リンク数（E列）を増やすことが目的です。
列内容型役割操作
A列NO（連番）integer記事の管理番号読み取りのみ
B列記事URLstring（URL）クロール対象URL・対象記事の識別子読み取りのみ
C列メインKW（GSCクリック最多）stringSTEP2の起点キーワード読み取りのみ
D列発リンク数integerこの記事から他記事への内部リンク数（参考値）読み取りのみ
E列被リンク数integer他記事からこの記事への内部リンク数。≤ 1 が対象抽出条件読み取りのみ
F列クリック数integerGSCクリック数（参考値）読み取りのみ
G列表示回数integerGSC表示回数（参考値）読み取りのみ
H列候補記事URL①string（URL）システム出力：対象記事へリンクを設置する候補記事のURL（1件目）書き込み
I列リンク設置箇所見出し①stringシステム出力：候補記事①内でリンクを設置するのに最適な見出し箇所書き込み
J列候補記事URL②string（URL）システム出力：対象記事へリンクを設置する候補記事のURL（2件目）書き込み
K列リンク設置箇所見出し②stringシステム出力：候補記事②内でリンクを設置するのに最適な見出し箇所書き込み
L列候補記事URL③（任意）string（URL）システム出力：対象記事へリンクを設置する候補記事のURL（3件目）書き込み
M列リンク設置箇所見出し③（任意）stringシステム出力：候補記事③内でリンクを設置するのに最適な見出し箇所書き込み
N列処理済みフラグstring「done」で再処理スキップ。再実行するには削除する書き込み

05 処理フロー設計
5.1 メイン処理フロー
flowchart TD
    START([処理開始]) --> LOAD[入力CSV全データ読み込み]
    LOAD --> LOOP{未処理行あり?}
    LOOP -- No --> DONE([全処理完了])
    LOOP -- Yes --> CHECK{E列 被リンク数 ≤ 1\nかつN列が空?}
    CHECK -- No --> LOOP
    CHECK -- Yes --> STEP1[STEP1: 対象記事抽出\nB列URL・C列KW取得]
    STEP1 --> KW_CHECK{C列KWあり?}
    KW_CHECK -- Yes --> USE_KW[C列KWをそのまま使用]
    KW_CHECK -- No --> AUTO_KW[B列URLから記事を取得\ntitle/h1/h2/h3から\nKW自動検出]
    USE_KW --> STEP2
    AUTO_KW --> STEP2
    STEP2[STEP2: 関連記事候補探索\nKW完全一致・部分一致]
    STEP2 --> CLAUDE1[Claude API\nKW拡張・関連語生成]
    CLAUDE1 --> CAND[候補記事リスト生成\n自己参照・重複除外]
    CAND --> CAND_CHECK{候補記事あり?}
    CAND_CHECK -- No --> EMPTY[出力なしで\n処理済みフラグ書き込み]
    EMPTY --> LOOP
    CAND_CHECK -- Yes --> FETCH[STEP3: 記事HTML取得\nrequests + タイムアウト10秒]
    FETCH --> HTTP{取得成功?}
    HTTP -- No --> SKIP_LOG[スキップ・警告ログ\n次の候補へ]
    SKIP_LOG --> CAND_CHECK
    HTTP -- Yes --> PARSE[BeautifulSoup解析\ntitle/h1/h2/h3/本文]
    PARSE --> STEP4[STEP4: Claude API関連性判定\n100点・5観点スコアリング]
    STEP4 --> SCORE{スコア ≥ 60?}
    SCORE -- No --> CAND_CHECK
    SCORE -- Yes --> ADD[採用リストに追加]
    ADD --> COUNT{採用 ≥ 2件?}
    COUNT -- No --> CAND_CHECK
    COUNT -- Yes --> STEP5[STEP5: 出力CSV書き込み\nH列以降にURL・見出しを追記]
    STEP5 --> FLAG[N列に done フラグ書き込み]
    FLAG --> LOOP
5.2 エラー時処理フロー
発生箇所エラー内容処理フロー
STEP3HTTP 404・タイムアウト警告ログ出力 → 当該候補をスキップ → 次の候補へ進む
STEP4Claude API 5xx / レート制限0.5秒待機 → リトライ（最大2回）→ 失敗時はスキップ → 次の候補へ
STEP5Sheets API 書き込み失敗エラーログ出力 → 実行停止 → ユーザーに手動確認を要求
全体採用候補が2件未満閾値を60→40に引き下げ → 再評価 → それでも不足なら空欄で出力
5.3 クライアント運用フロー
手順担当操作内容
①クライアントCowork画面上でNYSEOデータ（CSV）を読み込む
②クライアントCowork上でエージェントを起動する
③システム（自動）STEP1〜5を自動実行し、出力CSV（H列以降にURL・見出しを追記）を生成する
④クライアント出力CSVのH列以降を確認し、提案内容をレビューする
⑤クライアントレビューOKの内容をもとに、H列の候補記事（WordPressの当該記事）を開き、I列の見出し箇所に対象記事へのリンクを手動で設置する
⑥クライアント再実行が必要な場合、出力CSVのN列の「done」フラグを削除してから再起動する
