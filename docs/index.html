01 要件定義書
1.1 プロジェクト概要

目的

SEOツールから出力したGoogle Spreadsheetを読み込み、被リンク不足記事（被リンク数E列≤1）に対して、関連性の高い他記事から内部リンクを設置する候補を自動提案し、SEO内部リンク構築業務を半自動化する。

💡 最終的な内部リンク設置はクライアント担当者様が確認・判断することを想定しています。WordPressへの自動反映は本フェーズでは対象外となります。

主要機能

  • 被リンク不足記事の自動抽出（E列 ≤ 1）
  • メインKW（C列）を起点とした関連記事探索（KW一致・部分一致・上位概念KW展開）
  • C列空欄時はSTEP3取得済みのh2/h3見出しをKWとして自動使用
  • article_cacheタブによるHTML解析結果のセッション間・複数ユーザー間での共有・再利用
  • Cowork内蔵AIによる「上位概念→下位詳細」パターン特化スコアリング（100点満点）
  • 内部リンク設置候補をSpreadsheetのH〜M列に書き込み
1.2 ユーザー・権限定義
ロール説明できることできないこと
システム運用者
エージェント実行者		 Cowork上でエージェントを起動する エージェント実行・再実行・ログ確認 WordPress自動投稿（本フェーズ対象外）
クライアント担当者
レビュアー		 Spreadsheetの提案結果を確認・レビューする SpreadsheetのH列以降確認・内部リンク実施の最終判断 エージェントの直接操作
👥 複数のユーザーが同一Spreadsheetを共有することで、実行結果を全員でリアルタイムに参照できます。
1.3 機能要件（5ステップ処理）
1
STEP1 — 対象記事抽出
  • SpreadsheetのE列（被リンク数）を全行読み取る
  • E列 ≤ 1 かつ H列が空白の行を対象に選定する（H列にデータがある行はスキップ）
  • 対象行のB列（記事URL）・C列（メインKW）を取得する
  • C列が空白の場合は「auto_detect」フラグを立て、STEP3取得後にh2/h3見出しをKWとして使用する
  • B列が空の場合のみその行をスキップしてログに記録する
2
STEP2 — 関連記事候補探索
  • メインKW（C列またはh2/h3から自動検出）とSpreadsheet内の全記事KWをKW完全一致・部分一致で比較する
  • Cowork内蔵AIを用いてKWの上位概念・まとめ記事KWを生成し探索範囲を拡張する
  • 対象記事自身のURL・すでに採用済みのURLは除外する
  • 最大20件の候補リストを生成してSTEP4へ渡す
3
STEP3 — 候補記事取得・解析（article_cacheタブ優先）
  • まずarticle_cacheタブを確認し、キャッシュ済みURLはHTTP取得をスキップする
  • キャッシュがない場合のみHTTPSリクエストを送信する（タイムアウト10秒）
  • BeautifulSoupで <title>・<h1>・<h2>（最大15件）/<h3>（最大20件）・本文テキスト（先頭1500文字）を抽出する
  • 取得成功時はarticle_cacheタブに保存する（次回・他ユーザーの実行で再利用）
  • HTTP失敗（404・タイムアウト等）はスキップ・警告ログ出力・処理継続する
  • 最大2回リトライ後に失敗した場合は候補から除外する
4
STEP4 — AI関連性判定（上位概念→下位詳細パターン特化）
  • Claude Sonnetが読者層・地理的一致・自然さ・トピック深度の4項目・100点満点で全候補を一括採点する
  • スコア ≥ 60点の記事を採用候補とする（未満は「該当なし」）
  • 採用候補から「リンクを貼る箇所の見出し（recommended_heading）」もAIが合わせて特定する。H3/H4見出しを優先し、見当たらない場合のみH2を使用する
  • recommended_headingが空欄の場合はスコアが60点以上でも除外する（リンク設置箇所が特定できない候補は採用しない）
  • 採用なしの場合はH列に「該当なし」と書き込み（空白のままにしない）
5
STEP5 — Spreadsheetへ書き込み
  • 採用候補をスコア降順で並び替え、上位2〜3件をSpreadsheetのH〜M列に書き込む
  • H列: 候補記事URL① / I列: リンク設置箇所見出し①
  • J列: 候補記事URL② / K列: リンク設置箇所見出し②
  • L列: 候補記事URL③（任意） / M列: リンク設置箇所見出し③（任意）

03 AI判定ロジック設計
3.1 関連性スコアリング設計（4項目・100点満点）
🔗 リンク方向：候補記事（リンクを貼る側）→ 対象記事（リンク先・被リンクを増やしたい記事）
判定モデル：Claude Sonnet が全候補を1回の呼び出しで一括採点します。
判定観点配点判定内容
読者層の一致25点利用者側・提供者側・管理者側を自律推定し、両記事の読者層が一致するか評価。不一致の場合は30点以下に制限
地理的一致15点地名を含む記事同士は区・市・駅名レベルで一致が必須。隣接エリアは不一致扱い。非地域記事（ハウツー・用語解説）への地域記事リンクは禁止（0点）
読者にとっての自然さ35点リンクが読者の記事内での流れを妨げないか。文脈上の自然さを評価
トピックの深さと関連性25点表面的なキーワード一致でなく、内容レベルの接点があるか評価。同業種カテゴリが同じだけでは不十分（候補記事の見出し・本文に対象記事のKWが登場することが必要）
合計100点60点以上かつrecommended_heading非空を採用
3.2 判定基準・閾値設定
スコア評価採用判定
80〜100点強く関連あり✅ 優先採用（最上位で出力）
60〜79点関連あり✅ 通常採用
0〜59点関連なし・不十分❌ 除外（「該当なし」と出力）
📌 追加フィルタ：スコアが60点以上でも recommended_heading（リンク設置見出し）が空欄の候補は除外されます。AIがリンク設置箇所を特定できない場合は採用しません。

STEP4: 関連性判定プロンプト（4項目・100点満点）

あなたはSEO専門家です。「対象記事」に対する複数の「候補記事」の内部リンク適性を一括評価してください。

## 対象記事（内部リンクを受ける側）

## 採点基準（合計100点）
1. 読者層の一致（25点）
   利用者側・提供者側・管理者側を自律推定し、両記事の読者層が一致するか。不一致なら30点以下
2. 地理的一致（15点）
   区・市・駅名レベルで一致するか。隣接エリアは不一致扱い。
   地域横断と判定する場合は候補記事内に具体的な地名の明示が必要。
   非地域記事（ハウツー・用語解説）への地域記事リンクは禁止（0点）
3. 読者にとっての自然さ（35点）
   リンクが読者の記事内での流れを妨げないか
4. トピックの深さと関連性（25点）
   表面的なKW一致でなく、内容レベルの接点があるか。
   同業種カテゴリが同じだけでは不十分。候補記事の見出し・本文に対象記事のKWが登場することが必要

## 出力形式（JSON配列のみ・説明不要）
[{"url": "候補URL", "score": 整数(0-100), "reason": "理由（1文）", "recommended_heading": "H3/H4優先・なければH2・なければ空文字"}, ...]

04 データ設計
4.1 Spreadsheet列定義（Sheet1）
📋 A〜G列は記事一覧データ（入力・読み取りのみ）、H〜M列はシステムの出力領域です。
🔗 リンク方向：H列以降に出力される「候補記事URL」は、その記事から対象記事へ内部リンクを新たに設置する記事です。
列内容型役割操作
A列NO（連番）integer記事の管理番号読み取りのみ
B列記事URLstring（URL）クロール対象URL・対象記事の識別子読み取りのみ
C列メインKW（GSCクリック最多）stringSTEP2の起点キーワード（空欄の場合はh2/h3を使用）読み取りのみ
D列発リンク数integerこの記事から他記事への内部リンク数（参考値）読み取りのみ
E列被リンク数integer他記事からこの記事への内部リンク数。≤ 1 が対象抽出条件読み取りのみ
F列クリック数integerGSCクリック数（参考値）読み取りのみ
G列表示回数integerGSC表示回数（参考値）読み取りのみ
H列候補記事URL①string（URL）システム出力：この記事から対象記事へリンクを設置する候補（1件目）書き込み
I列リンク設置箇所見出し①stringシステム出力：候補記事①内でリンクを設置するのに最適な見出し箇所書き込み
J列候補記事URL②string（URL）システム出力：候補記事（2件目）書き込み
K列リンク設置箇所見出し②stringシステム出力：候補記事②内の見出し箇所書き込み
L列候補記事URL③（任意）string（URL）システム出力：候補記事（3件目）書き込み
M列リンク設置箇所見出し③（任意）stringシステム出力：候補記事③内の見出し箇所書き込み

05 処理フロー設計
5.1 main.py処理順序
flowchart TD
    START([py main.py URL\n--api フラグで APIモード]) --> INIT[SheetsClient初期化\nSheets接続・article_cache読み込み]
    INIT --> LOAD[Sheet1全データ読み込み\n全記事のURLとKWをインデックス化]
    LOAD --> STEP1[STEP1: E列≤1 かつ H列空の\n対象記事を抽出]
    STEP1 --> FETCH[フェーズ1: 未キャッシュ記事を全件HTTP取得\narticle_cacheタブに保存]
    FETCH --> KW_EXT[フェーズ2: KW未設定記事のメインKW抽出\nCLIモード: Haiku逐次\nAPIモード: Haiku並列]
    KW_EXT --> TARGET_LOOP[対象記事ごとの処理ループ]
    TARGET_LOOP --> STEP2[STEP2: KW一致スコアリング\n候補不足時はKW拡張で補完\n上位20件を選出]
    STEP2 --> STEP4[STEP4: AI関連性スコアリング\n上位→下位パターン特化・60点以上を採用\nCLIモード: Sonnet逐次\nAPIモード: Sonnet 5並列]
    STEP4 --> STEP5[STEP5: H〜M列に書き込み\n採用なし→「該当なし」\n技術的失敗→空欄のまま]
    STEP5 --> NEXT{次の対象記事あり?}
    NEXT -- Yes --> TARGET_LOOP
    NEXT -- No --> DONE([全処理完了])
5.2 クライアント運用フロー
💬 実行方法：Coworkのチャット欄にSpreadsheet URLを伝えると、py main.py <URL> が自動実行されます。
👥 共有について：実行結果はSpreadsheetに直接書き込まれるため、共有メンバー全員がリアルタイムで確認できます。
手順担当操作内容
①クライアントSEOツールのCSVデータをSpreadsheetに取り込み
②クライアントサービスアカウントのメールアドレスをSpreadsheetに編集者として共有
③運用者Coworkのチャット欄に「Spreadsheet URLを伝える」
④システム（自動）STEP1〜5を自動実行し、H〜M列に提案結果を書き込む。article_cacheタブにHTML解析結果を保存
⑤全員SpreadsheetのH列以降を確認・レビュー
⑥クライアントレビューOKの候補記事（H列）を開き、I列見出し箇所に手動で内部リンクを設置
⑦運用者再実行の場合はH〜M列のデータを削除して再実行（article_cacheはそのまま保持）
5.3 CLIオプション一覧

py main.py <URL> [オプション] で指定できるオプションの一覧です。

オプション説明使用例
--limit N処理する対象記事数をN件に制限（テスト・部分実行用）--limit 10
--row N指定した1行（スプレッドシート行番号）のみ処理--row 42
--rows N,M,...複数行を強制再処理（赤字で上書き）。H列に既存データがある行も再処理--rows 15,32,79
--reprocess-all全行を強制再処理（赤字で上書き）。--limit と組み合わせ可能--reprocess-all --limit 50
--apiClaude APIを直接呼び出すAPIモードで実行（5並列・高速）--api
--mid中間モデル（claude-sonnet）を使用（--apiと併用）--api --mid
--lean省リソースモードで実行（候補数を削減）--lean
🔄 再処理について：--rows / --reprocess-all で再処理した行は赤字で書き込まれます。通常実行（H列空白のみ対象）との区別に使います。
