01 要件定義書
1.1 プロジェクト概要

目的

NYSEOデータを格納したGoogle Spreadsheetを読み込み、被リンク不足記事（被リンク数E列≤1）に対して、関連性の高い他記事から内部リンクを設置する候補を自動提案し、SEO内部リンク構築業務を半自動化する。

💡 最終的な内部リンク設置はクライアント担当者様が確認・判断することを想定しています。WordPressへの自動反映は本フェーズでは対象外となります。

主要機能

  • 被リンク不足記事の自動抽出（E列 ≤ 1）
  • メインKW（C列）を起点とした関連記事探索（KW一致・部分一致・上位概念KW展開）
  • C列空欄時はSTEP3取得済みのh2/h3見出しをKWとして自動使用
  • article_cacheタブによるHTML解析結果のセッション間・複数ユーザー間での共有・再利用
  • Cowork内蔵AIによる「上位概念→下位詳細」パターン特化スコアリング（100点満点）
  • 内部リンク設置候補をSpreadsheetのH〜M列に書き込み
1.2 ユーザー・権限定義
ロール説明できることできないこと
システム運用者
エージェント実行者		 Cowork上でエージェントを起動する エージェント実行・再実行・ログ確認 WordPress自動投稿（本フェーズ対象外）
クライアント担当者
レビュアー		 Spreadsheetの提案結果を確認・レビューする SpreadsheetのH列以降確認・内部リンク実施の最終判断 エージェントの直接操作
👥 複数のユーザーが同一Spreadsheetを共有することで、実行結果を全員でリアルタイムに参照できます。
1.3 機能要件（5ステップ処理）
1
STEP1 — 対象記事抽出
  • SpreadsheetのE列（被リンク数）を全行読み取る
  • E列 ≤ 1 かつ H列が空白の行を対象に選定する（H列にデータがある行はスキップ）
  • 対象行のB列（記事URL）・C列（メインKW）を取得する
  • C列が空白の場合は「auto_detect」フラグを立て、STEP3取得後にh2/h3見出しをKWとして使用する
  • B列が空の場合のみその行をスキップしてログに記録する
2
STEP2 — 関連記事候補探索
  • メインKW（C列またはh2/h3から自動検出）とSpreadsheet内の全記事KWをKW完全一致・部分一致で比較する
  • Cowork内蔵AIを用いてKWの上位概念・まとめ記事KWを生成し探索範囲を拡張する
  • 対象記事自身のURL・すでに採用済みのURLは除外する
  • 最大20件の候補リストを生成してSTEP4へ渡す
3
STEP3 — 候補記事取得・解析（article_cacheタブ優先）
  • まずarticle_cacheタブを確認し、キャッシュ済みURLはHTTP取得をスキップする
  • キャッシュがない場合のみHTTPSリクエストを送信する（タイムアウト10秒）
  • BeautifulSoupで <title>・<h1>・<h2>/<h3>・本文テキスト（先頭1500文字）を抽出する
  • 取得成功時はarticle_cacheタブに保存する（次回・他ユーザーの実行で再利用）
  • HTTP失敗（404・タイムアウト等）はスキップ・警告ログ出力・処理継続する
  • 最大2回リトライ後に失敗した場合は候補から除外する
4
STEP4 — AI関連性判定（上位概念→下位詳細パターン特化）
  • Cowork内蔵AIが「候補記事が対象記事の上位概念・まとめ記事か」を軸に100点満点でスコアリングする
  • 同じジャンルの横並び記事（例: 品川の風俗街↔鶯谷の風俗街）は低スコアとなる
  • スコア ≥ 60点の記事を採用候補とする
  • 候補が2件未満の場合は閾値を40点に下げて再判定する
  • 採用候補から「貼る箇所の見出し」もAIが合わせて提案する
5
STEP5 — Spreadsheetへ書き込み
  • 採用候補をスコア降順で並び替え、上位2〜3件をSpreadsheetのH〜M列に書き込む
  • H列: 候補記事URL① / I列: リンク設置箇所見出し①
  • J列: 候補記事URL② / K列: リンク設置箇所見出し②
  • L列: 候補記事URL③（任意） / M列: リンク設置箇所見出し③（任意）

2.7 セキュリティ考慮事項
  • サービスアカウントJSONはプロジェクトフォルダ外の専用フォルダに保管する

  • Google Sheets APIのスコープは spreadsheets（読み書き）のみに限定する

03 AI判定ロジック設計
3.1 関連性スコアリング設計（上位→下位パターン特化）
🔗 リンク方向：候補記事（リンクを貼る側）→ 対象記事（リンク先・被リンクを増やしたい記事）
想定パターン：「風俗の種類まとめ」（上位概念）→「デリヘルスタッフの仕事内容」（下位詳細）のような構造が高スコアになります。
判定観点配点判定内容
上位概念・まとめ記事関係0〜40点候補記事が「種類まとめ」「ガイド」「特集」で、対象記事がその1要素になっているか
読者の誘導自然性0〜30点候補記事を読んで「もっと詳しく知りたい」と思ったとき、対象記事が答えになるか
文脈への含まれやすさ0〜30点候補記事の文脈内に対象記事のトピックが自然に含まれるか
合計0〜100点

水平リンクは低スコアになります

同じジャンルの別地域・別サービスの横並び記事（例: 品川の風俗街↔鶯谷の風俗街）は、上位概念関係がないためスコアが10点以下になります。

3.2 判定基準・閾値設定
スコア評価採用判定
80〜100点強く関連あり✅ 優先採用（最上位で出力）
60〜79点関連あり✅ 通常採用
40〜59点やや関連あり⚠️ 候補が2件未満の場合のみ採用（閾値下げ時）
0〜39点関連なし❌ 除外
3.3 プロンプト設計

STEP2: 上位概念KW生成プロンプト

あなたはSEOの内部リンク構造を最適化する専門家です。
以下のメインキーワードに対して、「このキーワードの記事が特集ページとして
含まれるような上位概念・まとめ記事」で使われそうなキーワードを5〜10個生成してください。

メインKW: {target_kw}

出力形式（JSON配列）:
["上位概念KW1", "上位概念KW2", ...]

注意:
- 同階層・同テーマの記事（例: 別の地域の同ジャンル記事）はNGです
- 対象記事の内容を「まとめる側」「紹介する側」になるKWを出力してください
- 日本語で出力すること

STEP4: 関連性判定プロンプト（上位→下位パターン特化）

あなたはSEOの内部リンク構造を最適化する専門家です。

## 内部リンクの方向
候補記事（リンクを貼る側）→ 対象記事（リンク先・被リンクを増やしたい記事）

## 対象記事（被リンクを増やしたい記事）
- KW: {target_kw}
- URL: {target_url}

## 候補記事（リンクを設置する側）
- タイトル: {candidate_title}
- URL: {candidate_url}
- 主要見出し: {candidate_headings}
- 本文冒頭: {candidate_body}

## 採点基準（合計100点）
1. 候補記事が対象記事の「上位概念・まとめ記事」になっているか（40点）
   - 高得点: 候補記事が「種類まとめ」「ガイド」「特集」で、対象記事がその1要素
   - 低得点: 同じジャンルの別地域・別サービスの横並び記事（0〜10点）
2. 候補記事の読者が対象記事を読みたくなるか（30点）
3. 候補記事の文脈に対象記事のトピックが自然に含まれるか（30点）

## 出力形式（JSONのみ・余分なテキスト不要）
{"score": 整数(0-100), "reason": "判定理由（1〜2文）", "recommended_heading": "候補記事内でリンクを設置するのに最適な見出し"}
04 データ設計
4.1 Spreadsheet列定義（Sheet1）
📋 A〜G列はNYSEOデータ（入力・読み取りのみ）、H〜M列はシステムの出力領域です。
🔗 リンク方向：H列以降に出力される「候補記事URL」は、その記事から対象記事へ内部リンクを新たに設置する記事です。
列内容型役割操作
A列NO（連番）integer記事の管理番号読み取りのみ
B列記事URLstring（URL）クロール対象URL・対象記事の識別子読み取りのみ
C列メインKW（GSCクリック最多）stringSTEP2の起点キーワード（空欄の場合はh2/h3を使用）読み取りのみ
D列発リンク数integerこの記事から他記事への内部リンク数（参考値）読み取りのみ
E列被リンク数integer他記事からこの記事への内部リンク数。≤ 1 が対象抽出条件読み取りのみ
F列クリック数integerGSCクリック数（参考値）読み取りのみ
G列表示回数integerGSC表示回数（参考値）読み取りのみ
H列候補記事URL①string（URL）システム出力：この記事から対象記事へリンクを設置する候補（1件目）書き込み
I列リンク設置箇所見出し①stringシステム出力：候補記事①内でリンクを設置するのに最適な見出し箇所書き込み

5.1 main.py処理順序
flowchart TD
    START([py main.py SpreadsheetURL]) --> INIT[SheetsClient初期化\nSheets接続・article_cache読み込み]
    INIT --> LOAD[Sheet1全データ読み込み]
    LOAD --> STEP1[STEP1: E列≤1 かつ H列空の対象行を抽出]
    STEP1 --> HTML_LOOP[全記事HTMLループ]
    HTML_LOOP --> CACHE_CHECK{article_cache\nに存在?}
    CACHE_CHECK -- Yes → キャッシュ使用 --> NEXT_HTML
    CACHE_CHECK -- No --> HTTP[HTTP取得 + BeautifulSoup解析]
    HTTP --> SAVE[article_cacheタブに保存]
    SAVE --> NEXT_HTML[次の記事へ]
    NEXT_HTML --> HTML_DONE{全記事完了?}
    HTML_DONE -- No --> HTML_LOOP
    HTML_DONE -- Yes --> TARGET_LOOP[対象記事ごとの処理ループ]
    TARGET_LOOP --> KW_CHECK{C列KWあり?}
    KW_CHECK -- Yes --> USE_KW[C列KWを使用]
    KW_CHECK -- No（auto_detect） --> H2H3[キャッシュのh2/h3見出しをKWとして使用]
    USE_KW --> STEP2
    H2H3 --> STEP2
    STEP2[STEP2: KW一致 + AI上位概念KW展開で候補探索]
    STEP2 --> STEP4[STEP4: AI関連性スコアリング\n上位→下位パターン特化]
    STEP4 --> STEP5[STEP5: SpreadsheetのH〜M列に書き込み]
    STEP5 --> NEXT_TARGET{次の対象記事あり?}
    NEXT_TARGET -- Yes --> TARGET_LOOP
    NEXT_TARGET -- No --> DONE([全処理完了])
