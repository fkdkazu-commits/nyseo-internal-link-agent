仕組

このツールの仕組みと概要

セットアップ前に全体像を把握してください

何をするツールか

SEOツールから書き出した Google Spreadsheet を読み込み、被リンク数が少ない記事（E列 ≤ 1）に対して、サイト内の他記事から内部リンクを設置すべき候補を自動提案します。結果は Spreadsheet の H〜M 列に自動書き込みされます。

実行の流れ

Cowork（Claude Desktop Pro）のチャット欄に Spreadsheet の URL を貼り付けると、以下の順序で処理が進みます。

💬CoworkURL を貼り付け
→
🌐Chrome自動操作
→
🖥️ランナーサーバーバックグラウンド常駐
→
⚡PowerShell処理実行・ログ表示
  1. Cowork のエージェントが精度モード・AI モードを選択するよう案内します
  2. Cowork が Chrome を自動操作して処理を開始します
  3. PowerShell ウィンドウが自動で開き、リアルタイムでログが表示されます
  4. 処理完了後、Spreadsheet の H〜M 列に結果が書き込まれます

1

Python のインストール確認

すでにインストール済みの場合はスキップ可

スタートメニューから「PowerShell」を検索して開き、以下を実行してください。

PowerShell
py --version
✅
OK：Python 3.11.x のようなバージョンが表示されます → ステップ 2 へ進んでください。
⚠️
「py は認識されていません」と表示される場合：
python.org からインストーラーをダウンロードして実行してください。
インストール画面で 「Add Python to PATH」のチェックを必ず入れてください。
インストール後は PowerShell を一度閉じて再度開いてから py --version を再確認してください。
2

Google Chrome と Claude 拡張機能の確認

Cowork が Chrome を操作して処理を起動するために必要です

Chrome のインストール確認

Google Chrome がインストールされているか確認してください。

  • スタートメニューで「Chrome」を検索して起動できればインストール済みです
  • インストールされていない場合は google.com/chrome からダウンロードしてください
ℹ️
Chrome は 通常起動できる状態（ログインなしでも可）であれば問題ありません。Cowork が自動操作するため、普段 Chrome をメインブラウザとして使っていなくても構いません。

Claude Chrome 拡張機能のインストール

Cowork が Chrome を操作するために必要な公式拡張機能です。

  1. Chrome を開く
  2. Chrome ウェブストアで「Claude」を検索する（または Cowork の設定画面からリンクをたどる）
  3. 「Claude for Chrome」（Anthropic 製）を「Chrome に追加」する
  4. 拡張機能が追加されると、ブラウザ右上にアイコンが表示されます
✅
拡張機能バーに Claude のアイコン（橙色）が表示されていればインストール済みです。すでにある場合は何もしなくて構いません。
⚠️
Cowork の「Claude in Chrome」機能は この拡張機能がなければ動作しません。必ずインストールしてください。

  • スタートメニューで「Claude」を検索して起動できるか確認

プロジェクトフォルダの配置

管理者から受け取ったフォルダを PC に配置します

受け取った nyseo-internal-link-agent フォルダを PC 内の任意の場所に置いてください。

推奨の配置場所（日本語・スペースを含まないパス）：

推奨パス例
C:\Users\<ユーザー名>\Downloads\nyseo-internal-link-agent\
⚠️
フォルダパスに全角文字（日本語）や半角スペースが含まれると、コマンド実行時にエラーが発生することがあります。できるだけ英数字のパスに置いてください。

フォルダ内に以下のファイル・フォルダが含まれていることを確認してください。

nyseo-internal-link-agent/
├── main.py　　　　　← メイン処理
├── local_runner.py　← ランナーサーバー（常駐）
├── setup_once.ps1　 ← 初回セットアップスクリプト
├── requirements.txt　← 必要なライブラリ一覧
├── config.py
├── steps/
├── utils/
├── prompts/
└── docs/
5

Google サービスアカウント JSON の配置

認証ファイルをプロジェクト外の専用フォルダに保管します

管理者から受け取った JSON ファイルを以下の場所に配置します。

保存先パス
C:\Users\<ユーザー名>\.secrets\nyseo-agent-xxxxxxxx.json

PowerShell を開き、.secrets フォルダを作成してください（すでにある場合はスキップ）。

PowerShell
mkdir "$env:USERPROFILE\.secrets"

作成したフォルダに JSON ファイルをコピーしてください（エクスプローラーでのコピー＆ペーストで OK です）。

🔒
JSON ファイルはプロジェクトフォルダ内に置かないでください。
.secrets フォルダは git 管理外のため、誤ってファイルが共有・公開されるリスクがありません。
6

必要なライブラリのインストール

Python パッケージをインストールします（約 2〜5 分）

PowerShell でプロジェクトフォルダに移動し、以下を実行してください。

PowerShell
cd "C:\Users\<ユーザー名>\Downloads\nyseo-internal-link-agent"
pip install -r requirements.txt

インストール中は多数のログが流れます。最後に以下のような表示が出れば完了です。

Successfully installed anthropic-x.x.x beautifulsoup4-4.12.x gspread-6.x.x ...
（バージョン番号は異なる場合があります）
⚠️
「pip は認識されていません」と表示される場合：
Python のインストール時に PATH が設定されていない可能性があります。py -m pip install -r requirements.txt で代替してください。それでも失敗する場合は Python を再インストールしてください（「Add Python to PATH」にチェック）。
7

初回セットアップスクリプトの実行

環境変数・自動起動登録・サーバー起動を自動で行います

同じ PowerShell（プロジェクトフォルダにいる状態）で以下を実行してください。

PowerShell
.\setup_once.ps1
⚠️
「このスクリプトはシステムで実行できません」と表示される場合は、PowerShell を管理者として実行し直してから以下を入力して再試してください。
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser

スクリプトの進行（全 4 ステップ）

[1/4] Google サービスアカウントのパス設定

デフォルトのパスが表示されます。ステップ 5 で配置したパスと同じであれば Enter を押すだけです。

[1/4] Google Sheets Service Account Current: （現在の設定、初回は空欄） Default: C:\Users\<ユーザー名>\.secrets\nyseo-agent-xxxxxxxx.json Enter path (or press Enter to use default): ← Enter を押す OK: File found. GOOGLE_SERVICE_ACCOUNT set.

別のパスに保存した場合：フルパスを入力して Enter を押してください。「File not found」と出た場合はパスを再確認してください。

[2/4] Anthropic API キー（任意・APIモード使用時のみ）

CLI モードのみ使用する場合は Enter でスキップしてください。

API モード（5 並列・高速処理）を使う場合は sk-ant-… 形式のキーを入力してください。

[2/4] Anthropic API Key Required only for API mode. Press Enter to skip for CLI mode only. API Key (sk-ant-..., or Enter to skip): ← CLI のみなら Enter Skipped. CLI mode only.
ℹ️
API キーは後から変更できます。変更する場合は setup_once.ps1 を再実行してください。
API キーを設定しても CLI モードには影響しません。CLI モード実行時は API キーを使わない設計になっています。
[3/4] Windows 起動時の自動起動登録

PC を再起動するたびにランナーサーバーが自動で起動するよう、Windows のスタートアップに登録します。

[3/4] Registering local runner server in Windows startup Registered: C:\Users\...\Start Menu\Programs\Startup\nyseo_runner.bat

スタートアップフォルダ（%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\）に nyseo_runner.bat が作成されます。

[4/4] ランナーサーバーの即時起動と確認

セットアップ完了後すぐにサーバーを起動し、正常に動いているか自動確認します。

[4/4] Starting local runner server now Server running: {"status": "idle"}   ================================================== Setup complete! ==================================================   Next steps: 1. Restart Cowork (Claude Desktop Pro) 2. Open the 内部リンクエージェント project in Cowork 3. Paste your Spreadsheet URL in the chat   The runner server will start automatically on every Windows boot. To change settings later, run this script again.
✅
「Server running: {"status": "idle"}」が表示されればセットアップ完了です。
⚠️
「Could not verify server start」と表示された場合：
サーバーが起動中の可能性があります。30 秒ほど待ってからブラウザで http://127.0.0.1:8765/status を開いて確認してください。
それでも接続できない場合は「トラブル対応」を参照してください。

Cowork の再起動とプロジェクト作成

設定を反映し、エージェント用プロジェクトを作成します

① Cowork を再起動する

  1. Cowork（Claude Desktop Pro）を完全に閉じる
    タスクトレイ（画面右下の通知領域）にアイコンがある場合は右クリックして「終了」してください

② プロジェクトを新規作成する

  1. 左サイドバーの「Projects」を開き、「+ New project」をクリックする

  3. 「Project instructions（プロジェクト指示）」の入力欄を開く

ℹ️

③ プロジェクト指示文をコピーする

⚠️
貼り付ける前に、指示文内の PROJECT_DIR のパスを自分のフォルダの実際の場所に書き換えてください。
例：C:\Users\yamada\Downloads\nyseo-internal-link-agent
Cowork プロジェクト指示文（全文コピー → 貼り付け）
# 内部リンク構築AIエージェント — Cowork実行手順

## プロジェクト設定（パスを変更する場合はここを編集）

```
PROJECT_DIR : C:\Users\<ユーザー名>\Downloads\nyseo-internal-link-agent
RUNNER_URL  : http://127.0.0.1:8765
```

## このエージェントの目的
SEOツールから出力したSpreadsheetを読み込み、被リンク不足記事（E列≤1）に対して
関連性の高い他記事から内部リンクを設置する候補を自動提案する。

## Coworkからの実行方法

ユーザーがSpreadsheetのURLを伝えたら、以下の手順を上から順番に実行する。

---

### STEP 1：精度モードの選択

> 精度モードを選択してください。
> - **高精度**（推奨）: KWをトークン単位で分割してスコアリング。候補記事を多く拾いやすい。
> - **中精度**: KW全体の文字列一致のみ。高速だが複合KWで候補が少なくなる場合がある。

---

### STEP 2：AIモードの選択

> AIモードを選択してください。
> - **CLIモード**: Cowork内蔵AIを使用。追加コストなし。処理は逐次（1件ずつ）。
> - **APIモード**: Anthropic API直接呼び出し。5並列処理で高速。ANTHROPIC_API_KEY が必要。

---

### STEP 3：ランナーサーバーの確認と実行

**① サーバーの状態確認**

Claude in Chrome を使って以下のURLを開く：
```
http://127.0.0.1:8765/status
```

- `{"status": "idle"}` → STEP 3② へ進む
- `{"status": "running"}` → 「現在別の処理が実行中です。完了後に再度お試しください。」とユーザーに伝える
- **接続できない場合** → 以下をユーザーに伝える：
  > 「ランナーサーバーが起動していません。PowerShellで以下を実行してください：」
  > ```powershell
  > py "C:\Users\<ユーザー名>\Downloads\nyseo-internal-link-agent\local_runner.py"
  > ```
  > 「起動後にもう一度URLを送ってください。」

**② 実行リクエストを送信**

選択結果に応じて Claude in Chrome で以下のURLを開く：

| 精度 | AIモード | URL |
|------|----------|-----|
| 高精度 | CLI | `http://127.0.0.1:8765/run?url=<URL>&mid=false&api=false` |
| 高精度 | API | `http://127.0.0.1:8765/run?url=<URL>&mid=false&api=true` |
| 中精度 | CLI | `http://127.0.0.1:8765/run?url=<URL>&mid=true&api=false` |
| 中精度 | API | `http://127.0.0.1:8765/run?url=<URL>&mid=true&api=true` |

`<URL>` はユーザーから受け取ったSpreadsheetのURLをそのまま入れる。

`{"status": "started"}` が返ってきたら：
> 「実行を開始しました。処理完了後にSpreadsheetをご確認ください。CLIモードは記事ごとに逐次処理、APIモードは5並列で一括処理します。」

---

### 処理の中断

処理中にユーザーが「止めて」「中断して」などと伝えた場合：

**① 中断リクエストを送信**

Claude in Chrome で以下のURLを開く：
```
http://127.0.0.1:8765/stop
```

`{"status": "stop_requested"}` が返ってきたら：
> 「中断シグナルを送信しました。現在処理中の記事が完了した後に停止します。Spreadsheetで処理済み記事（H列にデータあり）を確認できます。」

**② 中断後の状態**
- 処理済み記事のH〜M列はそのまま保持される
- 未処理記事のH列は空白のまま（次回実行時の再開ポイント）

---

### 処理の再開

中断後にユーザーが再開を希望した場合：
- 通常通り STEP 1〜3 を実施してSpreadsheet URLを送信するだけでよい
- H列が空白の記事だけが対象になるため、自動的に続きから処理される

> 「再開します。前回の続きから処理します（H列にデータがある記事は自動スキップされます）。」

---

## Spreadsheet構成

### データタブ（1枚目・既存）
| 列 | 内容 |
|---|---|
| A | NO |
| B | 記事URL |
| C | メインKW |
| D | 発リンク数 |
| E | 被リンク数（≤1が処理対象） |
| F | クリック数 |
| G | 表示回数 |
| H〜M | 出力（自動入力） |

### article_cacheタブ（自動作成）
初回実行時に自動作成される。取得済み記事のHTMLデータを保存し、
2回目以降の実行時に再取得をスキップする。

## 出力内容（H〜M列）
| 列 | 内容 |
|---|---|
| H | 候補記事URL①（この記事から対象記事へリンクを設置する） |
| I | リンク設置箇所の見出し① |
| J | 候補記事URL② |
| K | リンク設置箇所の見出し② |
| L | 候補記事URL③（任意） |
| M | リンク設置箇所の見出し③（任意） |

## ルール
- APIキー・認証情報はプロジェクトフォルダ外に保管すること
- 外部サイトへのHTTPリクエストはGET取得のみ
- エラーが発生した記事はスキップして処理を継続する
- H列にすでにデータがある記事は処理済みとしてスキップする
- ファイルやフォルダの作成・編集は絶対に行わない。コードの実行も行わない。ユーザーへの案内のみ行う
- ランナーサーバーに接続できない場合は、ユーザーに手動起動を案内するだけでよい。自分でサーバーを構築しようとしてはならない
- URLのパラメータ名は必ず mid と api を使うこと。mode や ai など別の名前に変えてはならない

Spreadsheet の準備

処理対象の Spreadsheet に必要な設定

① Google Spreadsheet を新規作成する

  1. ブラウザで drive.google.com を開く
  2. 「＋ 新規」→「Google スプレッドシート」をクリック
  3. シート名は任意でOK（例：内部リンク管理）

② CSV データをインポートする

  1. メニューの「ファイル」→「インポート」をクリック
  2. 「アップロード」タブで SEO ツールから書き出した CSV ファイルを選択
  3. インポート設定を以下の通りに設定する
ℹ️
インポート場所：現在のシートを置換する
区切り文字：カンマ
テキストを数値・日付に変換する：オン

インポート後、列構成が以下になっているか確認してください。

サービスアカウントへの編集権限付与

  1. Spreadsheet 右上の「共有」ボタンをクリック
  2. install.ps1 の STEP 10 で表示されたサービスアカウントのメールアドレスを入力
  3. 権限を「編集者」に設定して「送信」
⚠️
この設定をしないとツールが Spreadsheet を読み書きできません。必ず実施してください。

データタブ（1 枚目）の列構成

Spreadsheet の 1 枚目のタブが以下の列構成になっている必要があります。

列内容備考
ANO記事の通し番号

日常の使い方（セットアップ完了後）

毎回の実行手順

実行手順

  1. Cowork を開き、内部リンクエージェント プロジェクトを選択する
  2. チャット欄に Spreadsheet の URL を貼り付けて送信する
    例：https://docs.google.com/spreadsheets/d/xxxxx/edit
  3. 精度モードを選択する（エージェントが案内します）
    「高精度」または「中精度」を返答してください（詳細は「モード選択の目安」参照）
  4. AI モードを選択する（エージェントが案内します）
    「CLI モード」または「API モード」を返答してください（詳細は「モード選択の目安」参照）
  5. エージェントがサーバーの状態を自動確認する
    Chrome が自動で http://127.0.0.1:8765/status を開き、サーバーの状態を確認します
  6. エージェントが処理を自動開始する
    Chrome が自動で http://127.0.0.1:8765/run?url=… を開きます。{"status": "started"} が返ると処理開始です
  7. PowerShell ウィンドウが自動で開き、リアルタイムのログが表示される
    処理の進捗が 1 件ずつ表示されます。ウィンドウは開いたままにしておいてください
  8. 処理完了後、Spreadsheet を確認する
    PowerShell ウィンドウに「完了しました。このウィンドウを閉じてください。」と表示されたら終了です
✅
処理中に PowerShell ウィンドウを閉じると処理が強制終了されます。完了のメッセージが出るまで閉じないでください。途中で止めたい場合は下の「中断・再開」を使ってください。

処理の中断・再開

処理中に止める必要が生じた場合、以下の手順で安全に中断できます。処理済みのデータは保持され、再開時は続きから自動で再処理されます。

⏹ 中断する

  1. Cowork で「止めて」または「中断して」と送信する
    エージェントが自動で中断リクエストを送信します
  2. または、ブラウザで直接アクセスする
    http://127.0.0.1:8765/stop
    {"status": "stop_requested"} が返れば中断シグナルが送信されました
  3. 現在処理中の記事が完了した後に停止します
    PowerShell ウィンドウに「⏹ 中断シグナルを受信しました。」と表示されたら停止完了です
ℹ️
中断後も、処理済み記事（H 列にデータあり）のデータはそのまま Spreadsheet に残ります。未処理記事（H 列空白）だけが次回の処理対象になります。

▶ 再開する

  1. Cowork で同じ Spreadsheet URL を送信するだけです
    精度・AI モードの選択から通常どおり進めてください
  2. H 列が空白の記事だけが自動的に処理されます
    処理済み記事は自動スキップされるため、続きから再開されます

モード選択の目安

精度モードと AI モードの選び方

精度モード

モード仕組み向いているケース推奨
高精度 KW をトークン（単語）に分割してスコアリング。部分一致でも候補を拾える 通常はこちらを使用。複合語 KW でも候補が多く見つかる 推奨
中精度 KW 全体の文字列一致のみ。完全一致しないと候補に上がらない 処理を高速化したい場合・KW がシンプルな場合 状況次第

AI モード

モード仕組みコスト速度推奨
CLI モード Cowork の内蔵 AI（Claude）を使用。1 件ずつ逐次処理 追加コストなし（Claude Pro 契約内） 1 記事あたり 10〜20 秒程度 推奨
API モード Anthropic API を直接呼び出し。5 並列処理 API 使用料が発生（1 サイト約 $10〜15 程度） CLI の約 3〜5 倍高速 高速が必要な場合
ℹ️
API モードを使うには ANTHROPIC_API_KEY の設定が必要です。setup_once.ps1 の [2/4] で設定するか、再実行して追加してください。

AI 採点基準（100点満点 / 60点以上を採用）

以下の4項目を合計した点数が 60 点以上の候補記事のみ、内部リンク先として出力されます。

採点項目配点判定内容
読者層の一致 25点 候補記事と対象記事の想定読者が同じかを判定。「使う側・提供する側・管理する側」など立場が異なれば不一致とみなし、以降の評価も低スコアになる
地理的一致 15点 どちらかの記事に地名（都道府県・エリア・駅名など）が含まれる場合、両記事が同じ地域を扱っているかを確認。異なる地域の記事同士は低スコア。地名がない場合は満点扱い
読者にとっての自然さ 35点 候補記事を読んでいる読者が、対象記事へのリンクを見て「読みたい」と感じる文脈があるかを評価。無理やり挿入すると読者の流れを妨げる場合は低スコア
トピックの深さと関連性 25点 キーワードが表面的に一致しているだけでなく、内容レベルで接点があるかを評価。同じ大カテゴリでも具体的なトピックに重なりがない場合は低スコア
⚠️
AI の判定はあくまで自動評価です。出力された候補が実際のサイトの文脈に合わない場合は、担当者が判断して設置を見送ってください。

Q「ランナーサーバーが起動していません」と Cowork に表示される

PC 起動後にサーバーがまだ起動していないか、停止しています。PowerShell で手動起動してください。

PowerShell
py "C:\Users\<ユーザー名>\Downloads\nyseo-internal-link-agent\local_runner.py"

「内部リンクエージェント Runner: http://127.0.0.1:8765」と表示されたらサーバーが起動しています。PowerShell は閉じずに、Cowork で再度 URL を送信してください。

ℹ️
このウィンドウを閉じるとサーバーも停止します。処理中は開いたままにしてください。次回からは PC 起動時に自動起動します（setup_once.ps1 で登録済み）。
Q処理が途中で止まった / 手動で PowerShell ウィンドウを閉じた

そのまま再実行するだけで OK です。

H 列にデータが書き込まれた記事は次回実行時に自動でスキップされ、続きから処理されます。Cowork に同じ Spreadsheet URL を送信し直してください。

  • H 列にすでにデータが入っている場合は処理済みとしてスキップされます
  • サービスアカウントに 編集権限が付与されているか
