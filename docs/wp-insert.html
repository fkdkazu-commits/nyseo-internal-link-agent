01 要件定義書
1.1 プロジェクト概要

目的

内部リンク構築AIエージェントがGoogle Spreadsheetに出力した提案結果（H〜M列）を読み込み、WordPress記事の指定見出しセクション末尾にブログカード（リンク）を自動挿入する。クライアントが手動でWordPressを開いてリンクを設置する作業を自動化することで、内部リンク構築業務を完全自動化する。

💡 本ツールは内部リンク構築AIエージェント（v1.2）の後続ツールです。エージェントの実行→Spreadsheet確認・承認→本ツールで自動挿入、という運用フローを想定しています。

主要機能

  • SpreadsheetのH〜M列（候補記事URL・見出し）を読み込む
  • 候補記事ごとにWordPress REST APIで記事コンテンツを取得する
  • 指定見出しのセクション末尾にブログカードを挿入する
  • クラシックエディタ（HTML）とGutenbergブロックエディタの両方に対応する
  • リンク形式（URLのみ / aタグ）をCowork実行時に選択できる
  • 挿入結果をSpreadsheetのN〜P列に記録する（成功・失敗ステータス）
1.2 前提条件
⚠️ 本ツールは内部リンク構築AIエージェントの出力結果を入力として使用します。エージェントを先に実行し、Spreadsheetのレビュー・承認を完了してから本ツールを実行してください。
前提条件内容
内部リンクエージェント実行済み SpreadsheetのH〜M列に候補記事URL・見出しが書き込まれていること。「該当なし」の行は自動スキップされる
Spreadsheet承認済み クライアント担当者がH〜M列をレビューし、問題ない行のみ本ツールで処理する（全行一括 or 個別行指定で実行可能）
WordPress Application Password設定済み WordPress管理画面でApplication Passwordを発行し、環境変数に設定していること（WP 5.6以降の標準機能）
article_cacheタブに記事タイトルあり aタグ形式でリンクを挿入する場合、アンカーテキストにarticle_cacheのtitle列を使用するため、事前にキャッシュが必要
1.3 機能要件（処理フロー）
1
STEP1 — Spreadsheetから挿入対象を読み込む
  • SpreadsheetのSheet1を全行読み込む
  • H列が空白または「該当なし」の行はスキップする
  • N列（挿入済みフラグ）が「済み」の行はスキップする（再実行時の重複防止）
  • H列・J列・L列のURLと、I列・K列・M列の見出しをセットで取得する（最大3セット/行）
  • --row N オプションで特定行のみ処理することもできる
2
STEP2 — WordPress記事を取得する
  • 候補記事のURL（H列・J列・L列）をもとにWordPress REST APIで記事を検索・取得する
  • URLのスラッグ部分を使ってAPIエンドポイント GET /wp/v2/posts?slug=xxx で検索する
  • 記事が見つかれば投稿IDと現在のコンテンツ（content.raw）を取得する
  • 記事が見つからない場合はスキップ・警告ログを出力して処理継続する
3
STEP3 — 見出しセクションを特定する
  • I列・K列・M列の見出しテキストをもとに、記事コンテンツ内の該当見出しを探す
  • クラシックエディタの場合：HTMLの <h2>〜<h4> タグで文字列一致を確認する
  • Gutenbergの場合：ブロックJSONの core/heading ブロックで文字列一致を確認する
  • 見出しが見つからない場合はスキップ・警告ログを出力して次のセットへ進む
  • 見出し発見後、そのセクションの「末尾」（次の同レベル以上の見出しの直前）を挿入位置とする
4
STEP4 — ブログカードを挿入する
  • Cowork実行時に選択されたリンク形式・エディタ形式に従って挿入コンテンツを生成する
  • クラシックエディタ：HTML文字列に <p>[リンク]</p> を挿入する
  • Gutenberg：paragraphブロックまたはhtmlブロックをブロックJSONに追加する
  • 1行につき最大3セット（H+I列、J+K列、L+M列）を処理する。各セットは同じ記事への挿入が必要なため、まとめて1回のPUT更新にする
5
STEP5 — WordPress記事を更新し結果を記録する
  • POST /wp/v2/posts/{id} で更新済みコンテンツを書き込む
  • 成功した場合、SpreadsheetのN列に「済み」・O列に更新日時・P列に挿入数を記録する
  • 失敗した場合、N列に「エラー」・O列にエラー内容を記録する
1.4 実行時選択仕様（Coworkが実行前に確認）

本ツールはCowork（Claude Desktop）から実行します。Coworkが以下2つの選択肢を実行前にユーザーに確認します。

Q1. エディタ形式は？
  • クラシックエディタ
    HTMLとして記事コンテンツを操作
  • Gutenbergブロックエディタ
    ブロックJSONとして記事コンテンツを操作
Q2. リンク形式は？
  • URLのみ
    WordPress側のブログカード自動展開に任せる
  • aタグ
    <a href="URL">記事タイトル</a>
    アンカーテキストはarticle_cacheのtitleを使用
💡 クライアントのWordPressがどちらのエディタかは、初回実行前に口頭確認します。確認できた場合はデフォルト値として環境変数に設定することも可能です（WP_EDITOR=classic など）。

2.4 エディタ別コンテンツ処理方式

クラシックエディタ（HTML形式）

処理方式
コンテンツ取得REST API content.raw フィールドにHTMLが格納されている
見出し特定BeautifulSoupで <h2>〜<h4> タグを検索し、テキストが一致する要素を探す
挿入位置該当見出しから次の同レベル以上の見出しタグの直前。セクション末尾に相当する
挿入形式<p>URL</p> または <p><a href="URL">タイトル</a></p>
更新編集後のHTML文字列を content フィールドにPUTする

Gutenbergブロックエディタ（JSON形式）

処理方式
コンテンツ取得REST API content.raw にブロックシリアライズ形式（HTML + ブロックコメント）が格納されている
ブロック解析Gutenbergのブロック形式は <!-- wp:heading --> のようなHTMLコメントで識別できる。正規表現でブロックを分割する
見出し特定wp:heading ブロック内のテキストが一致するブロックを探す
挿入位置該当見出しブロックから次の同レベル以上の見出しブロックの直前
挿入形式（URLのみ）<!-- wp:paragraph --><p>URL</p><!-- /wp:paragraph -->
挿入形式（aタグ）<!-- wp:paragraph --><p><a href="URL">タイトル</a></p><!-- /wp:paragraph -->
更新編集後のブロック文字列を content フィールドにPUTする

2.6 エラー処理
エラー種別対応処理継続
WordPress認証失敗（401）エラーログ出力・実行停止（認証情報を確認）❌ 停止
記事が見つからない（404）該当行をスキップ・N列に「エラー: 記事が見つかりません」を記録✅ 継続
見出しが見つからない該当セットをスキップ・警告ログ出力。他のセットは処理継続✅ 継続
記事更新失敗（APIエラー）N列に「エラー」・O列にエラー内容を記録してスキップ✅ 継続
Google Sheets接続失敗エラーログ出力・実行停止❌ 停止
N列「済み」の行スキップ（重複挿入防止）✅ 継続
2.7 セキュリティ考慮事項
  • WordPress Application Passwordはプロジェクトフォルダ外の専用フォルダに保管する
  • 環境変数 WP_URL / WP_USER / WP_APP_PASSWORD でCredentialsを参照する（コードにハードコードしない）
  • WordPress REST APIはHTTPS経由のみ使用する（HTTP不可）
  • 記事の読み取り（GET）と更新（POST）のみ実施。記事の新規作成・削除は行わない
  • .gitignore で .env をGit管理対象外に設定（既存設定を流用）

03 データ設計
3.1 Spreadsheet列定義（Sheet1）
📋 A〜M列は内部リンクエージェントの既存列定義です。本ツールはH〜M列を入力として読み込み、N〜P列に挿入結果を書き込みます。
列内容本ツールでの役割
H列候補記事URL①入力：この記事にリンクを挿入する
I列リンク設置箇所見出し①入力：H列の記事内でリンクを挿入するセクションの見出し
J列候補記事URL②入力（任意）
K列リンク設置箇所見出し②入力（任意）
L列候補記事URL③入力（任意）
M列リンク設置箇所見出し③入力（任意）
N列挿入ステータス出力：「済み」/ 「エラー」/ 「スキップ」
O列処理日時 / エラー内容出力：成功時は更新日時・失敗時はエラーメッセージ
P列挿入件数出力：その行で実際に挿入した件数（0〜3）
3.2 WordPress REST API仕様

認証

Authorization: Basic base64("{WP_USER}:{WP_APP_PASSWORD}")
Content-Type: application/json

記事検索（URLスラッグで検索）

GET {WP_URL}/wp/v2/posts?slug={slug}&_fields=id,slug,content

レスポンス例:
[{
  "id": 1234,
  "slug": "article-slug",
  "content": {
    "raw": "<!-- wp:heading --><h2>見出しテキスト</h2><!-- /wp:heading -->..."
  }
}]

記事更新

POST {WP_URL}/wp/v2/posts/{id}
Body: {
  "content": "更新後のコンテンツ（HTML or Gutenbergブロック文字列）"
}

レスポンス: 200 OK → 更新成功
            401 → 認証エラー
            404 → 記事が見つからない

環境変数

変数名内容設定場所
WP_URLWordPressサイトのURL（例: https://example.com）install.ps1 で自動設定
WP_USERWordPressの管理者ユーザー名install.ps1 で自動設定
WP_APP_PASSWORDApplication Password（スペース区切りの24文字）install.ps1 で自動設定
GOOGLE_SERVICE_ACCOUNTサービスアカウントJSONのパス（既存）既存設定を流用

4.2 クライアント運用フロー

推奨フロー（レビューあり）

手順担当操作内容
①運用者Coworkのチャット欄にSpreadsheet URLを伝えて内部リンクエージェントを実行
②Coworkエージェント完了後、自動的に確認を出す：
「WordPressへの自動挿入も続けますか？はい or いいえ」
③運用者「いいえ」を選択してSpreadsheetでH〜M列を確認・承認（URLと見出しが正しいか目視確認）
④運用者Coworkのチャット欄に「WordPress挿入を実行して」と伝える
⑤Cowork「エディタ形式」「リンク形式」を確認してから py main_wp.py <URL> を自動実行

⑧運用者エラー行は原因を調査し、必要に応じて --row N で個別再実行

①運用者Coworkのチャット欄にSpreadsheet URLを伝えて内部リンクエージェントを実行
②Coworkエージェント完了後：「WordPressへの自動挿入も続けますか？」の確認を出す
③運用者「はい」を選択。Coworkが警告を表示してから「エディタ形式」「リンク形式」を確認
④システム（自動）WordPress記事にリンクを挿入し、N〜P列に結果を記録
⑤全員SpreadsheetのN列で「済み」「エラー」を確認
💡 単独実行にも対応：エージェントのみ・WP挿入のみをCoworkのチャット欄から個別に指示できます。内部リンクエージェントは py main.py、WP挿入は py main_wp.py として完全に独立したスクリプトです。
