Feature Guide — WordPress Auto Insert (v1.4.3)

WordPress 自動反映機能
導入・操作手順書

内部リンクエージェントが提案した候補（H〜M 列）を、WordPress 記事に自動挿入する機能の手順書です。
初期インストール（install.bat）と内部リンクエージェントの実行が完了していることが前提です。
1

WordPress 認証情報の設定

初回のみ必要な設定です

設定が必要なもの

WordPress REST API を使って記事を更新するため、以下の3つの情報が必要です。

項目内容例
WP URL WordPress サイトの URL https://example.com
WP ユーザー名 WordPress のログインユーザー名 admin
アプリケーションパスワード WordPress のアプリケーションパスワード xxxx xxxx xxxx xxxx xxxx xxxx

設定手順（install.bat で行います）

初期インストール時に実行した install.bat を再実行すると、STEP 8「WordPress サイト設定」で以下を入力できます。

  1. WordPress サイト URL を入力する（例：https://example.com）
  2. ユーザー名・アプリケーションパスワード を入力する
  3. 設定が ~/.secrets/nyseo_sites.json に保存される（キーは WordPress URL のドメイン名）
ℹ️
複数の WordPress サイトを運用する場合は、繰り返し追加できます。各サイトは WordPress URL のドメイン名（例：example.com）で自動的に識別されます。

アプリケーションパスワードの発行手順

  1. WordPress 管理画面 → 「ユーザー」→「プロフィール」を開く
  2. ページ下部の「アプリケーションパスワード」セクションまでスクロール
  3. 「新しいアプリケーションパスワード名」に任意の名前を入力（例：内部リンクツール）
  4. 「新しいアプリケーションパスワードを追加」ボタンをクリック
  5. 表示されたパスワード（スペース区切り）をコピーして install.bat に入力する
⚠️
アプリケーションパスワードは発行時の1回しか表示されません。必ずコピーしてから入力してください。
2

実行前の確認・操作手順

Spreadsheet のレビュー後、Cowork から実行します
⚠️
WordPress への挿入は取り消しが手間です。
実行前に必ず Spreadsheet の H〜M 列（内部リンク候補）を確認してください。おかしな候補があれば、H 列の値を削除（空白に戻す）してから実行してください。

WordPress 挿入の開始方法

WordPress 挿入は Cowork から依頼して開始します。

ℹ️
1サイトのみ登録の場合は確認なしで自動的に選択されます。複数サイトを登録している場合は、実行時にどのサイトに挿入するかエージェントが確認してきます。
Cowork から依頼して開始する
Spreadsheet の H〜M 列を確認・承認してから実行することを推奨します。
  1. Spreadsheet の H〜M 列を確認・承認する（問題のある行は H 列を空白にしてスキップ）
  2. Cowork を開き、内部リンクエージェント プロジェクトを選択する
  3. 「WordPress に挿入してほしい」と送信し、Spreadsheet URL を伝える
  4. エージェントがサイト（複数登録時）・リンク形式（3種類）・実行範囲（1記事のみ / 一括）を順に確認してくるので選択する
  5. Chrome が自動で起動し、Cowork 上に「Allow」ボタンが表示されたらクリックする
  6. PowerShell ウィンドウが開き、処理が進む（完了まで閉じないでください）
  7. 1記事のみを選択した場合は、完了後に Spreadsheet と WordPress のプレビューで表示を確認してから「一括実行」を依頼する
⚠️
はじめて実行するときは必ず「1記事のみ」でテスト実行してください。
WordPress プレビューで挿入位置・リンク形式を確認してから一括実行することを強く推奨します。
挿入結果がおかしいと感じた場合は、ツール販売元までお問い合わせください。
NYマーケティング：seo@ny-marketing.co.jp

処理完了後の確認

  1. Spreadsheet の N/O/P 列で結果を確認する

処理ログの見方（PowerShell ウィンドウ）

================================================== WordPress 内部リンク自動挿入ツール 開始 ================================================== データ読み込み完了: 20 件 [1/20] https://example.com/article-1 候補① https://example.com/article-10 → 見出し「見出しA」 → Gutenberg 記事 / リンク挿入: 1件 / スキップ: 0件 → 済み [2/20] https://example.com/article-2 候補① https://example.com/article-5 → 見出し「見出しB」 → Classic 記事 / セクション内に既存リンクあり → スキップ → 済み（スキップあり） ================================================== 全処理完了。Spreadsheet の N/O/P 列をご確認ください。 ==================================================
3

リンク形式の選び方

Cowork が確認してきます。3種類から選んでください
形式WordPress での見た目向いているケース推奨
URL挿入
--link url		 Gutenberg は wp:embed ブロック、クラシックは URL をそのまま挿入。WordPress の oEmbed 機能でブログカード表示を試みる。表示結果はテーマに依存 ブログカード表示を希望する場合。まず 1 記事でテスト表示を確認してから一括実行することを推奨 ブログカード推奨
aタグ
--link atag		 記事タイトル のようなテキストリンクとして挿入される 表示結果を確実にしたい場合。サイトのテーマに依存しない テキストリンク推奨
ショートコード
--link shortcode		 テーマ独自のショートコード形式で挿入される。テンプレート文字列（例：[related id={id} label=関連記事]）を実行時に入力する テーマ専用のショートコードを使って内部リンクを挿入したい場合 カスタム
ℹ️
ショートコードの {id} には Spreadsheet の A 列（No.）の値が自動的に入ります。
A 列の値が WordPress の投稿 ID と一致していることをあらかじめご確認ください。
⚠️
URL挿入でブログカードになるかはテーマによって異なります。
WordPress の oEmbed 機能に対応していないテーマでは、URL がそのままテキスト表示される場合があります。必ず 1 記事のみでテスト実行し、表示結果を確認してから一括実行してください。
ℹ️
エディタ形式（Gutenberg / クラシック）は自動判定されます。記事ごとにどちらのエディタで書かれているかを自動検出して挿入方法を切り替えるため、事前に指定する必要はありません。
4

N/O/P 列の見方

処理結果が Spreadsheet に記録されます
列内容説明
N処理ステータス「済み」「済み（スキップあり）」「エラー」など処理結果の概要
O処理日時 / エラー内容処理が完了した日時。エラー時はエラー内容が記録される
P挿入件数実際に WordPress へ挿入されたリンクの数（0〜3）

N 列のステータス一覧

表示内容意味対応
済み 正常に処理完了。1 件以上が挿入された 対応不要
済み（スキップあり） 一部の候補は既存リンクがあり挿入スキップ。1 件以上は挿入済み P 列の挿入件数を確認。必要なら手動で確認
スキップ（リンク済み） 対象記事の URL がすでに候補記事の本文に含まれていた（全候補スキップ） 対応不要。すでにリンクが設置済みです
警告（スキップあり） 指定した見出しが記事内に見つからず全候補がスキップされた Spreadsheet の I/K/M 列の見出し名が記事と一致しているか確認
エラー 接続エラーまたは API エラー WP_URL / WP_USER / WP_APP_PASSWORD の設定を確認して再実行
ℹ️
冪等性（重複防止）について：N 列に何らかの値が記録されている行（空欄以外）は再実行しても処理されません。誤って再実行しても2重挿入にはなりません。再処理が必要な場合は N 列を空白に戻してから実行してください。
5

セクション内リンクチェック（v1.3〜 / SWELL対応 v1.4.3〜）

見出しセクション内に既存リンクがある場合は自動スキップ

仕様

WordPress 記事に内部リンクを挿入する前に、対象の見出しセクション内に挿入先と同一の URL が既に存在するかチェックします。

  • aタグ・ブログカード・URLのみなど、形式にかかわらずURLの文字列が含まれていれば「既存リンクあり」と判定
  • SWELLテーマのブログカード（v1.4.3〜）：投稿IDで保存されるため raw コンテンツには URL が含まれないが、レンダリング済みの href を参照することで正しく重複検知する
  • 対象記事のURLが一致しない別のリンクはチェック対象外（同じセクションに複数の異なる記事へのリンクは許容）

同一URLが見つかった場合は、そのセクションへの挿入をスキップし、スキップ件数（P 列）を増やします。

✅
この仕様の目的：すでに手動でリンクを設置したセクションに重複して挿入されるのを防ぐためです。1つの見出しセクションに複数のリンクが集中することを回避します。

スキップされた場合の対応

N 列が「済み（スキップあり）」になっており、P 列にスキップ件数が記録されます。

  • スキップされた候補は WordPress には挿入されていません
  • 既存のリンクをそのままにしたい場合は対応不要です
  • どうしても挿入したい場合は、手動で WordPress 記事を編集してリンクを追加してください

トラブルシューティング

よくある問題と対処法
Q「WP_URL が設定されていません」と表示される

環境変数が設定されていないか、設定後に PowerShell を再起動していません。

  1. このページの「WordPress 認証情報の設定」手順で環境変数を設定する
  2. PowerShell を一度閉じて新しく開く（または PC を再起動）
  3. 再度実行する
Q「401 Unauthorized」エラーが出る

WordPress の認証情報が正しくありません。以下を確認してください。

  • WP_USER が WordPress のログインユーザー名（メールアドレスではなく）になっているか
  • WP_APP_PASSWORD がアプリケーションパスワード（ログインパスワードではない）になっているか
  • アプリケーションパスワードが有効になっているか（WordPress 管理画面 → ユーザー → プロフィール で確認）
QN 列が「スキップ（見出し不一致）」になっている

Spreadsheet の I / K / M 列に記録されている見出し名が、実際の WordPress 記事内の見出しと一致しませんでした。

以下を確認してください。

  • WordPress 記事を開き、I / K / M 列の見出しが記事内に存在するか確認する
  • 記事の見出しが後から変更されていないか確認する
  • 見出しを修正した場合は、I / K / M 列の値も更新して N 列を空白にして再実行する
Qリンクが挿入されたが意図しない場所に入った

WordPress 記事を直接編集して手動でリンクを削除してください。削除後は Spreadsheet の N / O / P 列を空白に戻し、H 列の候補も修正してから再実行してください。

ℹ️
N 列が「済み」のまま再実行しても処理されません。N 列を空白にすることで再処理の対象になります。
Q一部の記事だけ処理したい

Cowork に以下のように伝えてください。

  • 特定の行だけ処理：「No10 の行だけ WordPress に挿入して」→ --row 11 オプションで実行されます
  • 先頭から N 件まで処理：「No1〜20 だけ挿入して」→ --limit 20 オプションで実行されます
Qアップデート版が届いた。どう適用すればよいか

以下の手順で上書き適用できます。環境変数（WP_URL など）の再設定は不要です。

  1. 受け取った zip を展開する
  2. nyseo-internal-link-agent\ フォルダの中身を既存フォルダに上書きコピー
  3. PowerShell で以下を実行する
PowerShell
cd "C:\Users\<ユーザー名>\Downloads\nyseo-internal-link-agent"
pip install -r requirements.txt

4. ランナーサーバーを再起動する

local_runner.py も上書き更新されるため、zip 適用後は必ず再起動が必要です。既存の PowerShell ウィンドウを閉じて、以下で起動し直してください。

PowerShell
py "<インストール先>\local_runner.py"

5. 通常通り実行してください。
